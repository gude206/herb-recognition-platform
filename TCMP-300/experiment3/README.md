# 实验三：模型量化与结构化剪枝

> GitHub 同步说明：仓库 `results/` 保存本次实验结果及数据指纹，对应本机的 `runs/`；不含模型权重、训练检查点、原始图片及运行日志。报告正在整理且存在待修正问题，本次不上传报告成稿。仓库版 `execution_permissions.json` 默认禁止长任务，与本地授权记录不同；`config.json` 原样保留供哈希追溯，其中的绝对路径需在本地自行适配。

本目录的实验范围为实验二 ResNet-50 的 **INT8 静态量化**和 **L1 结构化通道剪枝及微调**。两条路线均从同一原模型独立出发，分别与原模型比较。

## 给报告撰写者的注意事项

- 量化校准实际使用了带随机裁剪和翻转的训练预处理，与原计划的固定 Resize、CenterCrop 不一致；验证选型与最终导出分别重新校准，尚未证明二者为同一量化模型。下表的测试结果是最终导出模型的现存记录，不应表述为严格按原计划完成的校准结果。
- 测速实际反复使用验证集前 1 张或前 8 张，而不是循环使用前 32 张；表中吞吐量由每轮中位延迟推算，不能称为按总样本数和总耗时计算的平均吞吐量。见 `run.py` 的 `cmd_benchmark`。
- 剪枝达到计算量下降目标，**未达到精度下降不超过 3 个百分点的目标**。按平台规则停止不代表已证明充分收敛。
- 历史 0–127 量化尝试属于本次量化实验，但旧版三档验证分数的完整原始记录当前未找到；不要把无法独立追溯的数字当成已核实结果，也不要把校准范围与精度的关系写成已证实的单一原因。
- 当前报告中已有的速度数值是模型推理计时，不包含读图、预处理、网络或网页耗时；GPU 剪枝有实测加速，不宜写成没有加速。现有计时不能证明加速差异的具体硬件瓶颈。
- 任务书要求量化误差的类别分析；现有 `runs/evaluation/per_class_cpu_A.csv` 和 `per_class_cpu_Q.csv` 可供分析，已有热力图只比较 A 与 P。

## 模型与数据

| 标记 | 模型 | 对比设备 |
|---|---|---|
| A | 实验二基础版 ResNet-50，`../runs/resnet50_7030_baseline/best.pt` 第 19 轮 | CPU、GPU |
| Q | A 独立生成的 CPU INT8 静态量化模型 | CPU |
| P | A 独立生成的 30% 通道剪枝模型，经微调后选取第 18 轮 | GPU |

使用 TCMP-300 的 300 类数据：训练 36,324 张、验证 11,030 张、测试 4,735 张。训练图片从原训练目录读取；验证集和测试集沿用固定清单。测试集划分指纹为 `a54b9f2faa7b68053ebaba873a184ef171eaf58407672ab3d464df432b593f09`。

## 已保存的测试结果

每个模型/设备组合的现存记录均为 4,735 张、batch 1；Q、P 分别与同设备的 A 比较。参数与 FLOPs 的 Q 数值是逻辑值，FLOPs 只统计 Conv 和 Linear，1 MAC = 2 FLOPs。

| 模型 | 设备 | Top-1 | Top-5 | 参数 | 主算子 FLOPs | TorchScript 文件 |
|---|---|---:|---:|---:|---:|---:|
| A | CPU | 79.9155% | 92.3126% | 24,122,732 | 8.1755 G | 92.53 MiB |
| Q | CPU | 79.0074% | 91.7423% | 24,122,732 | 8.1755 G | 23.74 MiB |
| A | GPU | 79.9155% | 92.3126% | 24,122,732 | 8.1755 G | 92.53 MiB |
| P | GPU | 74.4667% | 89.4403% | 15,586,826 | 5.2569 G | 59.95 MiB |

Q 相对 A 的 Top-1 下降 0.9081 个百分点，文件缩小 74.35%；P 相对 A 的 Top-1 下降 5.4488 个百分点，参数减少 35.39%，主算子 FLOPs 减少 35.70%。这些是现存实验结果，需结合上面的流程问题解释。

剪枝微调运行 26 轮，记录的平台停止条件均满足；第 18 轮验证 Top-1 最好，为 73.8078%。训练准确率上升而验证 CE 后期升高，存在过拟合迹象。只对 30% 档进行了微调，不能据此宣称它是微调后的最优剪枝比例。
