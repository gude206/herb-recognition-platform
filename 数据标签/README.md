# 中草药智能识别与知识平台

基于 React、TypeScript、Vite 的植物识别与本草知识平台。图片识别连接相邻 TCMP-300 项目的 ResNet50；草药图鉴和科普文章由后端从 MySQL 提供，模型保留 300 个稳定类别，公开图鉴为 299 条有来源的植物资料，科普文章按审核与来源条件发布。AI 问答由后端连接 DeepSeek，注册、用户登录和管理员登录使用真实后端账号与会话。

## 本地查看

在父目录 D:\Study\AI全栈开发 中执行 ./start-platform.ps1，脚本等待前后端健康检查通过后报告就绪。打开 http://127.0.0.1:5173/herbs 浏览图鉴，或打开首页上传植物图片。接口文档为 http://127.0.0.1:8000/docs 。执行 ./stop-platform.ps1 可停止本脚本记录的实例；启动失败会清理本次进程。

也可以分别运行 ../TCMP-300/start-api.ps1 和 npm run dev -- --host 127.0.0.1 --port 5173 --strictPort。不要重复启动已占用端口的服务。

## 图鉴数据

原始资料文件为 ../TCMP-300/data/author_tcmp_300/tcmp-info-20250329.csv，全部 103 个字段已导入项目 MySQL 的 `plant_catalog`。后端读取数据库，保留原文件作为导入与校验来源。植物 ID tcmp-001 至 tcmp-300 与识别结果一致；资料来源、审核状态和第 51 类的身份冲突保持不变。

图鉴支持名称、学名、别名、药材名和传统功效搜索，关键词最多 200 字；参数错误、超时、断网分别提示。支持科、属、分布地区筛选，药材功效、药性与器官部位筛选，24 条分页、名称排序、最近浏览优先和网格/列表切换。从图鉴进入详情后，返回会保留筛选、排序与分页。地区选项按来源分布文字匹配，不属于完整地理编码或定位判断。

详情按活体植物展示身份、分布、生境、海拔、花果/孢子期和器官特征，并独立列出药材的基原、部位、加工、性味和传统记载。来源链接、资料版本、字段缺口和审核状态可追溯。原资料中文科属保留原分类体系，可能与规范科属不同。

原始资料保留在数据库及 CSV 中；公开图鉴展示 299 条来源资料，其中 278 条具备可直接采用的分布证据。名称冲突的 tcmp-051 不公开详情；缺少来源的字段与未获授权的参考图片不显示，不将自动摘录声称为专家审定。

## 配置与构建

需要 Node.js 20 或更新版本。安装依赖后执行 npm run dev；生产构建执行 npm run build；状态与导航检查执行 npm test。Vite 命令显式读取 vite.config.ts，配置编译输出保存在 .build/。退出当前路由的看板、关于页及其专属资源归档在 archive/，ECharts 已从当前依赖中移除。

复制 .env.example 为 .env。默认配置：

    VITE_API_BASE_URL=http://127.0.0.1:8000
    VITE_USE_MOCK=true
    VITE_MOCK_RECOGNITION=false
    VITE_MOCK_HERBS=false
    VITE_MOCK_ARTICLES=false

图片识别演示由 VITE_MOCK_RECOGNITION 控制；公开图鉴与文章始终读取后端的已发布内容。文章默认读取后端列表和正文，加载失败显示错误与重试按钮，不用示例数据伪装请求成功。VITE_MOCK_HERBS 和 VITE_MOCK_ARTICLES 不再开启公开演示回退。登录和注册不受 VITE_USE_MOCK 控制，必须连接真实后端与 MySQL。修改环境变量后重启 Vite。

文章在 MySQL 中保存标题、分类、摘要、正文、封面路径、发布状态和审核来源。原 7 篇课程示例保留为后台草稿；只有完成审核且提供公开来源的正式文章才能发布。

识别默认使用实验三 INT8 模型，结果区显示模型名称、推理耗时和页面展示耗时。图片识别与问答的成功响应通过 `result` 读取，错误提示通过 `msg` 读取。

## DeepSeek 问答配置

编辑相邻后端的 `../TCMP-300/.env`，在 `DEEPSEEK_API_KEY=` 后填入密钥。接口地址、模型、temperature、生成 token 上限和超时均在该文件中；完整参数说明见后端 `.env.example`。首次安装需执行后端的 `pip install -r requirements-api.txt` 并启动 `start-api.ps1`。

后端每次问答读取配置，修改 `.env` 后下一次问答即生效；进程环境中同名变量优先。密钥只留在后端，不放进前端 `VITE_*` 配置。问答不受 `VITE_USE_MOCK` 控制，不会用模拟回复替代请求失败。

首页助手右上角提供历史对话（时钟）与新对话（带加号的气泡）入口。历史列表可搜索问题、回答和植物名称，点击后恢复并继续追问；新对话从空白记录开始，同一植物可以保存多段独立对话。每次请求仅携带当前对话最近 6 轮成功问答；切换对话或植物期间，旧回答仍写回发送时的对话。

成功对话保存在后端 MySQL，前端历史入口从数据库加载。未登录时继续使用浏览器随机访客身份及原有本机缓存；登录后使用账号归属，完整消息不持久缓存到 localStorage，仅在 sessionStorage 保留当前账号的对话选择与草稿。登录或注册时可选择一次性关联当前访客问答和识别记录，关联后旧访客令牌失效；跨浏览器登录同一账号可读取已保存记录。数据库从已保存消息获取最近六轮上下文，失败的问答不写入半条记录。恢复历史时沿用该对话原来的植物参考，显示在助手上方。植物资料（包括审核状态）由后端附带给 DeepSeek，不发送原图片。密钥只留在后端，不进入浏览器历史记录。当前采用一次返回完整回答，不是流式输出。

草药识别卡片右上角提供识别历史入口，可按植物名称或上传文件名搜索，点击后恢复原图和完整模型结果。成功识别会将结果保存到 MySQL，原图保存在服务器本地。数据库安装与身份限制见父目录 `MYSQL_HISTORY.md`。

## 页面与接口

- /：真实图片识别、前五项预测与植物详情入口、来源知识卡片和最近浏览。
- /herbs、/herbs/:id：真实植物列表及详情。
- /knowledge：数据库科普文章列表与正文。
- /login：用户注册、用户登录、管理员登录与退出。
- /admin/articles：仅管理员可访问的文章维护；说明见父目录 `AUTH_ACCOUNTS.md`。
- 全局搜索提交至 /herbs?q=关键词；最近浏览只存于本机浏览器。

| 服务 | 路径 |
|---|---|
| 图鉴列表 | GET /api/v1/herbs |
| 真实筛选选项 | GET /api/v1/herbs/filters |
| 植物详情 | GET /api/v1/herbs/{id} |
| 本地参考图 | GET /api/v1/herbs/{id}/reference-image |
| 图片识别 | POST /api/v1/predict，multipart 字段 file |
| 识别示例 | GET /api/v1/recognition/samples |
| DeepSeek 问答 | POST /api/v1/chat，JSON 包含 message、可选 herb_id 和 history |
| 科普列表和详情 | GET /api/v1/articles、GET /api/v1/articles/{id} |

识别支持 JPG、PNG、WEBP，最大 10MiB；原始图片最长边不超过 10000 像素、总像素不超过 2500 万，缩放后预计像素不超过 100 万，极端长宽比会要求裁剪。单张图片的置信度是模型分数，不等于识别准确率；分布信息不会用于排除模型预测。识别页面保留前五项置信度、候选身份与审核提示，第 51 类明确显示身份冲突。上传预览与结果图片完整显示原比例，更换图片按钮位于预览下方。数据看板与关于项目已从路由、导航和首页入口移除。

测试后端：在 TCMP-300 目录执行 .venv-api\Scripts\python.exe -m unittest test_catalog test_api -v 。MySQL 内容迁移专项检查执行 `-m unittest test_content_mysql -v`，使用独立临时测试库验证全字段保留、图鉴和文章读取、发布状态与幂等导入。

本平台用于植物识别与传统本草知识学习，不提供在线诊断、处方或剂量建议。

## 公开内容范围

当前保留模型 300 类原始资料，公开图鉴为 299 条有来源的植物资料；名称冲突条目、未核验的药用/毒性/混淆内容及未获授权的训练参考图片不再公开。7 篇课程示例已下架为后台草稿。公开图鉴及文章始终读取后端，不再通过 VITE_MOCK_HERBS、VITE_MOCK_ARTICLES 展示演示内容。详情见父目录 `CONTENT_PUBLICATION.md`，账号历史不受影响。
